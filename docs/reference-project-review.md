## 不直接移植的行为

1. **接口不是本项目选定的新协议。** `api_client.py:150` 使用 `/v1/draw/completions`；Nano 使用 `/v1/draw/nano-banana`，字段为 `urls`、`shutProgress`。我们使用 `/v1/api/generate`、`images`、`replyType: async`，再 GET `/v1/api/result`。旧接口代码不能证明新接口支持完全相同的输入编码或响应结构。
2. **HTTP 超时被覆盖。** `api_client.py:82` 强制赋值 700，调用参数和配置不再决定生成请求的超时。本项目区分总等待期限、连接超时与单次请求超时，取消应独立响应。
3. **图片批次只取第一张。** `gpt_image_nodes.py:294` 和 `utils.py:201–202` 使用 `pil_images[0]`。新节点必须展开输入列表中的每个批次，不能丢掉第二张以后的图片。
4. **部分转换错误会跳过图片。** `nano_banana_2_nodes.py:224–225` 遇到 ValueError 继续执行；新节点应在提交前明确失败，避免引用图片与提示词顺序错位。
5. **输出顺序会受下载速度影响。** `api_client.py:204–213` 按 `as_completed` 顺序追加图片。新节点按上游 `results` 索引还原顺序。
6. **失败可能被包装成正常输出。** `gpt_image_nodes.py:252–264` 返回原图或 1×1 占位图。新节点报错终止当前依赖分支，不能让下游误存为生成成功。
7. **不同尺寸结果会被补边。** `utils.py:148–181` 将图像居中填充成统一大小后拼接。新节点输出图片列表，每项保持自身尺寸。
8. **模型字符串存在版本差异。** 参考代码包含 `nano-banana-2-cl-4k`，当前接口文档写 `nano-banana-2-4k-cl`。以选定新接口的当前文档为准，默认精简名单也不包含此变体。
9. **没有新的轮询/取消实现可直接复用。** 所读请求路径同步等待响应，相关 Python 文件未发现 `interrupt` / `cancel` / `poll` 处理。不能因单次请求超时很长，就推断它能及时响应工作流中断。
10. **说明文字滞后于实现。** `agents.md`/README 仍有图片上传、旧模型等描述；代码已经有直接 base64 路径。编码注释写 Data URL，但实际字符串没有 `data:image/png;base64,` 前缀。以执行代码为证据，并区分旧、新接口。

## 对当前设计的结论

保留“单节点入口 + 请求服务 + 图片转换 + 配置”的小规模结构；不沿用旧路由、固定多图片插口、并发生成数量参数、占位图失败回退或输出补边。

总等待期限默认关闭，避免本地因生成耗时长而提前结束；每次 HTTP 操作仍有有限超时。已取得任务 ID 的查询遇到暂时断网时，退避后查询同一任务，并允许用户随时中断。

新接口的 base64 契约仍属待实测项；本地旧实现增加了采用裸 PNG base64 的依据，未消除验证需要。
